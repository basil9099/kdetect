# Why the capture runs procfs -> sweep -> procfs

captured: 2026-08-19T11:50:33Z
kernel:   6.1.0-52-amd64
euid:     0
label: clean

Reproduce by hand:
    read /proc listing (pass A); sweep the pid space; read it again (pass B)

----------------------------------------------------------------------

A sweep takes seconds; a /proc walk takes milliseconds. Processes
start and exit in between, so the two views disagree on a clean
machine for reasons that have nothing to do with hiding.

The sandwich distinguishes them: an id the sweep saw that is absent
from BOTH walks, and still resolvable, cannot be explained by timing.
